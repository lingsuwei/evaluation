# onto-eval 设计范式

> **地位**：本文档是 onto-eval 与 onto-agent 联动的**架构宪法（精简版）**。  
> **用途**：评审任何需求、建议、实现方案前必须先对照；**超出范式时必须明示冲突**，不得默许或「先做了再说」。  
> **详设**：[架构设计说明书.md](./架构设计说明书.md) · [onto-agent-observability.md](./onto-agent-observability.md)

| 日期 | 2026-05-22 |
| 维护 | 与架构说明书 ADR 同步；P-25～P-27（RF-01～03） |

## 1. 范式总览（五大支柱）

| 支柱 | 一句话 | 详设 |
|------|--------|------|
| **Execution Fact Layer** | 一次推理 = AgentRun + RunStep + RunMetric + CheckpointResult；**非**单表 `agent_runs` 了事 | [架构评审-Execution-Fact-Layer.md](./架构评审-Execution-Fact-Layer.md) |
| **三域存储** | Langfuse = Raw SoR；PG = 物化事实；SQLite/PG 过渡期可并存 | §11 |
| **OTel 语义** | 契约在 **Attributes 字典 + JSONPath**，不在 `observation.name` | §8.8、onto-agent 契约 |
| **Span Tree** | 拓扑用 `run_span_nodes` 树，禁止 StepSequence 平铺做主模型 | §8.7 |
| **分级 Diff** | Outcome / Cost / Behavioral / Structural / Semantic 可插拔，MVP 先可算+人眼 | §10.8 |

## 2. 不可变约束（Invariant）

以下编号用于需求评审时引用（如 **违反 P-03**）。

| ID | 约束 | 违反时的默认处置 |
|----|------|------------------|
| **P-01** | 评测会话 ID 仅经 `build_eval_session_id` 单点生成 | **阻断** |
| **P-02** | `question_id` 仅在**数据集内**唯一；跨库对比用 `question_key` | **阻断** |
| **P-03** | 跨版本过程点 / Structural 契约**不得**以 `observation.name` 或 `type:name` 为主键 | **阻断**新需求；旧模板仅兼容 |
| **P-04** | 新过程点规则必须优先 `jsonpath` + `$.attributes.*`；`observation_name` 仅遗留 | **阻断**新模板首选 name |
| **P-05** | 聚合键用 `aggregate_key`（由 `agent.*` attributes 推导），禁止默认 `type:name` | **阻断** |
| **P-06** | 在线评测主路径**不得**同步全量扫 Langfuse 物化整棵树 | **阻断**；走 Job + Builder |
| **P-07** | Facets / 筛选主路径查 `agent_runs`（及物化表）；Langfuse 扫描仅**降级** | **降级**标注 |
| **P-08** | 推理拓扑存 Span Tree（`parent_id`），不用平铺 `step_index` 表达并行 | **阻断** |
| **P-09** | 不把 Langfuse 全量 observation 正文长期双写到 PG | **阻断** |
| **P-10** | BFF/前端不直连 Langfuse API（Key/CORS） | **阻断** |
| **P-11** | 发版不改历史行的 `logical_agent_id` / `agent.version`（新版本 = 新行） | **阻断** |
| **P-12** | `RunComparison` → 多行 `RunDiff`，扩展走 `diff_registry`，不堆单 JSON  blob | **阻断**大杂烩 diff |
| **P-13** | onto-agent 对稳定语义须上报 `agent.*`（见 observability 契约） | **降级** + 明示技术债 |
| **P-14** | 首期 Structural MVP = metric/event 聚合 + 双树 UI，非承诺全自动 path_diff | **延期**须写阶段 |
| **P-15** | **Diff**（Structural/Behavioral）只读 `run_span_nodes`（RunStep）+ `checkpoint_results` | **阻断**扫 Langfuse 做对比 |
| **P-16** | **Analytics / 报表** 只读 `run_metrics` + `agent_runs`；禁止默认 `scan_traces` | **阻断** |
| **P-17** | Langfuse 仅 **证据下钻**（trace/observation 详情）；分析 SoR 在本地事实层 | **阻断**套壳读路径 |
| **P-18** | `AgentRun` 不得以 `task_id`/`question_id` 为**全局**必填；核心为 `run_id`+`trace_id`；评测字段仅 `origin=evaluation` | **阻断**生产观测复用当前表 |
| **P-19** | Langfuse `session_id` 禁止全局 `{task_id}:{question_id}`；评测专用 `build_eval_session_id` | **阻断** |
| **P-23** | 跨任务题目标识用 **`dataset_item_id` / `question_key`**，不得仅 `question_id` 下标 | **阻断** 跨任务对齐失败 |
| **P-24** | 物化 enrich **仅** Runtime Fact Builder（含 Push）；Pipeline 不得写 tokens/span/metric | **阻断**（[COUP-C04](./架构评审-已知系统耦合-C01-C04.md)） |
| **P-25** | Analytics **禁止**裸扫 `run_metrics` KV；须视图/rollup（RF-01） | **阻断** |
| **P-26** | 对外 **禁止**承诺 Time Travel / Re-run / Replay（v1.15 已取消）；版本回归用重新评测 + Diff | **阻断** |
| **P-27** | Semantic 摘要 **≤1KB**、仅 llm/generation 节点；Judge 仅 Comparison（RF-03） | **阻断** |

## 3. 允许扩展（须说明阶段，不必改范式）

- 新 `diff_type` 注册（符合五类谱系之一）
- 新 `agent.*` 属性键（文档补 observability 表即可）
- JSONPath 能力增强（filter、数组下标）—— 不改变 P-03/P-04
- Postgres 迁移、Worker 队列实现细节
- M2 遗留 `observation_name` 规则只读兼容

## 4. 反模式（Anti-pattern，一律拒绝或标债）

| 反模式 | 原因 |
|--------|------|
| 「所有版本必须叫同一个 span name」 | 违反 P-03，绑定实现细节 |
| 「用 Python 函数名当过程点匹配条件」 | 同 P-03 |
| 「评测完成前同步拉全 trace 算分」 | 违反 P-06，阻塞 SLA |
| 「Facets 永远扫 Langfuse」 | 违反 P-07、P-16 |
| 「报表/Diff 为出图扫 Langfuse API」 | 违反 P-15、P-16、P-17 |
| 「P1 只做 agent_runs 就叫平台化」 | 违反 Execution Fact Layer 定义 |
| 「生产流量写入必填 task_id 的 AgentRun」 | 违反 P-18 |
| 「所有 trace 的 session 必须是 task:question」 | 违反 P-19 |
| 「RunStep 仅平铺表、无 parent_id」 | 违反 P-08；须用 `run_span_nodes` |
| 「StepSequence 列表做路径 diff」 | 违反 P-08 |
| 「SQLite 里存全量 observation input/output」 | 违反 P-09 |
| 「input/output_snapshot 存 Langfuse 全文」 | 违反 P-09；仅有界摘要 + trace 下钻 |
| 「一个 diff JSON 包含所有维度」 | 违反 P-12 |
| 「首期就上 Kafka + ClickHouse + 全自动拓扑 diff」 | 范围失控；见 §15 说明书 |
| 「评测完成 → 后台 Worker 循环调 Langfuse API 拉 trace」 | 违反 P-20；见 [架构评审-P2前战略修正.md](./架构评审-P2前战略修正.md) |
| 「生产 Run 必填 task_id / session=task:question」 | 违反 P-18、P-19、P-21 |
| 「跨任务对比只按 question_id 对齐」 | 违反 P-23；见 [C-01](./架构评审-已知系统耦合-C01-C04.md) |
| 「Pipeline 写 tokens_total 再让 Builder 覆盖」 | 违反 P-24 / COUP-C04（**已修正**：Pipeline 不写 token 头表） |

## 5. 需求评审协议（对你 / 对产品 / 对 AI）

### 5.1 何时必须走评审

- 新功能、字段、API、表结构
- 对 onto-agent 埋点/命名的要求
- 性能/存储/同步策略变更
- 任何「为了赶工」想破的契约

### 5.2 冲突等级

| 等级 | 含义 | AI / 研发动作 |
|------|------|----------------|
| **阻断** | 违反 §2 Invariant | **不得**默认实现；明示冲突 + 给合规替代方案 |
| **降级** | 可短期做但积累技术债 | 可实现但必须标注 `degraded: true`、还债项、阶段 |
| **延期** | 方向对但不在当前阶段 | 记入 backlog，写清 P 几验收 |

### 5.3 明示模板（超出范式时必须使用）

收到需求后，若命中 §2 / §4，回复中**必须**包含以下块（不可省略标题）：

```markdown
## 范式冲突说明

- **你的需求摘要**：（一句话复述）
- **冲突条目**：P-0x / 反模式 xxx
- **冲突等级**：阻断 | 降级 | 延期
- **为何不采纳**：（1–3 句，对照范式支柱）
- **合规替代方案**：（可落地的改法，如改报 agent.step.id、改 JSONPath 规则）
- **若你仍坚持**：需书面确认接受技术债 + 范围（否则不实现）
```

### 5.4 AI 助手义务（Cursor / 人工评审同等）

1. **先对照**本文件与 [架构设计说明书](./架构设计说明书.md)，再写代码或改文档。
2. 需求合理但表述撞车（如「统一 name」实际指 `agent.tool.name`）→ 先**澄清映射**到 Attributes，再实现。
3. 需求无理或超出阶段 → 使用 §5.3 模板，**拒绝或降级**；不因「用户明确要求」自动破范式。
4. 用户坚持破范式 → 记录在 §12 技术债或新 ADR，**不得** silently merge。

## 6. 需求速查表（常见越界 → 对策）

| 你可能的表述 | 范式判定 | 合规替代 |
|--------------|----------|----------|
| 「过程点匹配 span 名叫 xxx」 | 阻断 P-03 | `agent.step.id` + JSONPath |
| 「用 type:tool 聚合对比」 | 阻断 P-05 | `aggregate_key` / `agent.tool.name` |
| 「评测完立刻算完整 path diff」 | 延期 P-14 | 先 event_agg + 双树 UI |
| 「探索页 facets 只查 Langfuse」 | 降级 P-07 | 有 Run 时查 PG |
| 「question_id 全局唯一」 | 阻断 P-02 | 数据集内 id + question_key |
| 「前端直接调 Langfuse」 | 阻断 P-10 | BFF 代理 |
| 「把 trace 全同步进 SQLite」 | 阻断 P-09 | Job + 摘要物化 |
| 「一个接口返回所有 diff」 | 阻断 P-12 | RunComparison + 多 RunDiff |

## 7. 范式修订

- 修订本文件或 Invariant → **必须**在架构说明书 **ADR 表**登记（说明采纳理由与迁移）。
- 临时例外 → 仅限单任务/单客户，**不得**写入主路径；过期删除。
- 版本号：范式 v1.0 对应架构 v1.7 基线。
