P2.5 不是新架构阶段，而是 **P2～P5 代码在生产/预发环境的验收包**：Docker 默认 PostgreSQL、部署脚本、冒烟与 GitLab CI 门禁。

---

## 1. 脚本链路（推荐顺序）

| 步骤 | 脚本 | 用途 |
|------|------|------|
| 1 | `scripts/p0-bootstrap.sh`（Windows: `p0-bootstrap.ps1`） | 启动 postgres、Alembic/pg_bootstrap、构建并启动 app |
| 2 | `scripts/p0-smoke.sh`（Windows: `p0-smoke.ps1`） | API 健康、PG 连通、基础路由 |
| 3 | `scripts/p25-gate.sh`（Windows: `p25-gate.ps1`） | PG smoke 6 项 + ingest simulate（验证 Builder 逻辑） |
| 4 | [G-01 Runbook](./G-01-PG切换Runbook.md) Phase B～D | 有 SQLite 历史数据时迁移；生产 VM 签收 |

## 2. 环境变量要点

复制 `.env.example` → `.env`，至少确认：

```bash
# app 容器内（Compose 默认）
DATABASE_URL=postgresql+asyncpg://onto_eval:onto_eval_dev@postgres:5432/onto_eval_fact
POSTGRES_PORT=5433   # 宿主机映射，供 Alembic/smoke

# 事实摄入：Trace Sync Worker（唯一物化路径，v1.23 起默认开启）
TRACE_SYNC_WORKER_ENABLED=true
```

SQLite 回退仅用于本地调试，不含 Runtime Fact 视图与 PG 集成测试路径。

## 4. GitLab / GitCode CI

仓库根目录 `.gitlab-ci.yml` 三阶段：

| Stage | Job | 内容 |
|-------|-----|------|
| check | `ci-check` | 冲突标记扫描 + `docker-compose.yml` YAML 校验（`scripts/ci-check.sh`） |
| test | `backend-test` | `pytest -m "not integration and not postgresql"`（L1，约 341 项） |
| build | `frontend-build` | `npm ci && npm run build` |

**启用**：GitCode 仓库 → 设置 → CI/CD → 启用 Pipeline。MR 与分支 push 自动触发。

本地预检：

```bash
bash scripts/ci-check.sh
cd backend && python -m pytest -q -m "not integration and not postgresql"
cd frontend && npm run build
```

## 6. 常见问题

| 现象 | 处理 |
|------|------|
| Docker 内连不上 agent | `ONTO_AGENT_BASE_URL=http://host.docker.internal:5055`（仅评测调推理时需要，非事实摄入依赖） |
| PG connection refused | 容器内用 `@postgres:5432`；宿主机用 `@127.0.0.1:5433` |
| CI backend-test 失败 | 本地复现同上 pytest 命令；勿依赖 integration/postgresql 标记用例 |
| 镜像 build 拉取失败 | `.env` 设置 `FRONTEND_BASE_IMAGE` / `PYTHON_BASE_IMAGE` 镜像代理（见 `.env.example`） |
