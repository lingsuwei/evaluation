# 架构评审 — P2 前战略修正（数据摄入 · 领域 · Replay）

> **日期**：2026-05-22  
> **地位**：P2 落地前的**强制门禁**；不做则 P3 需推翻 Sync Worker 与 `agent_runs` 列模型。  
> **关联**：[架构设计说明书 v1.10](./架构设计说明书.md) §11、§12、§14.24；[设计范式 v1.2](./设计范式.md) P-20～P-22；ADR-027～029。

---

## 1. 背景与态度

v1.8～v1.9 已确立正确方向：**Execution Fact Layer**、Langfuse = Collector、本地 SQL 为分析 SoR。

v1.22 战略修正：**Agent 双写 Push 已完全取消**（非降级可选）。为减少对 Agent 的依赖、保证评测通用性，onto-eval 以 `internal_sync`（legacy_pull Worker）为唯一主路径，Agent 只需保证 Langfuse trace 入库。Trace 业务打点由 eval 侧独立实现，不依赖 Agent 侧维护任何 eval 专属埋点契约。

v1.23 战略修正：**Webhook/Push 摄入路径全部移除**。`/trace/ingest/webhook` 和 `/trace/ingest/push` 端点已删除，`FACT_INGEST_MODE` 配置项已取消。唯一物化路径为 Trace Sync Worker。

**结论**：onto-eval 通过 `internal_sync` Worker 主动拉 Langfuse API 物化 trace；不依赖 Agent Push 或 Langfuse Webhook。

## 2. 修正 1 — 事实摄入主路径（ADR-027 修订）

### 2.1 原则（P2 起）

- **Agent 双写 Push 已完全取消**：`/trace/ingest/push` 端点已移除，Agent 无需配置 `ONTO_EVAL_BASE_URL` / `ONTO_EVAL_PUSH_ENABLED`。
- **唯一物化路径**：`internal_sync`（Trace Sync Worker）拉取 Langfuse API 物化 trace。
- **Webhook/Push 已移除（v1.23）**：`/trace/ingest/webhook` 端点也已移除，不再依赖外部推送。
- Agent 只需保证 Langfuse trace 入库；Trace 业务打点由 eval 侧独立实现。

### 2.2 目标架构

```text
唯一主路径：internal_sync（legacy_pull Worker）
  推理结束 → Agent Langfuse SDK flush
  eval Pipeline → trace_sync_jobs 入队
  Trace Sync Worker → Langfuse API → Builder → synced

可选路径：Langfuse Webhook
  推理结束 → Agent Langfuse SDK flush
  Langfuse 回调 → POST /trace/ingest/webhook → Builder → synced

已废弃：onto-agent Push（/trace/ingest/push）
  Agent 双写 Push 已完全取消，不作为物化路径
```

### 2.3 实现要点

| 项 | 说明 |
|----|------|
| 接收端 | `POST /trace/ingest/webhook`（可选，Webhook 路径） |
| **配置步骤** | 见 [Langfuse-Webhook配置指南.md](./Langfuse-Webhook配置指南.md) |
| 物化 | 统一入口 `fact_ingest_service.ingest_trace_payload()` → `runtime_fact_builder` |
| 配置 | `FACT_INGEST_MODE=legacy_pull`（默认）；`TRACE_SYNC_WORKER_ENABLED=true` |
| 评测 Pipeline | `legacy_pull` 模式下 `trace_sync_status=pending`，入队 pull job |
| 运维 | `trace_sync_jobs` 为生产主路径核心表；Webhook 到达时直接物化，不依赖 job |

### 2.4 技术债迁移

| 旧债 | 新状态 |
|------|--------|
| TD-OPS-01 Worker 与 API 同进程 | **默认开启**（主路径）；可拆分独立进程 |
| P1.5 Sync 骨架 | **升级为当前主路径**；Push 已废弃 |

## 3. 修正 2 — `eval_context` 解绑 Task/Question（ADR-028）

### 3.1 原则

**AgentRun = 一次纯粹推理**（`run_id` + `trace_id` + `origin`）。评测业务语义 **不得**作为 Run 的必填列或全局 session 键。

### 3.2 表结构（目标，PG 为 JSONB）

| 字段 | 说明 |
|------|------|
| `origin` | `evaluation` \| `live` \| `replay` |
| `eval_context` | JSONB；评测时有 `task_id`、`dataset_id`、`question_id`、`run_index`；生产为空 |
| ~~`task_id` 等独立列~~ | **废弃**；过渡期双写镜像列，P2 PG 迁移后删除 |

**索引（PG）**：`GIN (eval_context)`；部分索引 `WHERE origin='evaluation'` 上 `(eval_context->>'task_id', eval_context->>'question_id')`。

**禁止**：`session_id = task_id:question_id` 作为生产/Live 会话 ID（仅 `build_eval_session_id` 用于评测 Langfuse 会话）。

### 3.3 代码过渡

- `services/eval_context.py`：`build_eval_context` / `parse_eval_context` / `get_eval_field`
- `create_agent_run_started`：写 `eval_context` + 镜像列（SQLite 兼容）
- Facets：优先 `eval_context`，回退列

## 4. 修正 3 — Replay 隔离字段（ADR-029）

在 **`run_span_nodes`**（P2 建表）预置：

| 字段 | 类型 | 说明 |
|------|------|------|
| `is_deterministic_io` | BOOLEAN | P5 Replay：该节点回放时是否应**重算**（false=确定性 IO，走 mock） |
| `mock_response_payload` | JSONB | 上次拦截的 payload；Replay 时直接返回 |

无此字段则 P5 无法区分「重放 LLM」与「重放工具固定响应」，Replay 方案必返工。
