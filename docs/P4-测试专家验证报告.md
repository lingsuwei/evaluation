## 5. 代码审查发现

### 5.1 后端 — 无阻塞缺陷

| 检查项 | 结论 |
|--------|------|
| 读路径无副作用 | ✅ GET 不 commit、不 insert RunDiff |
| 双树对齐逻辑 | ✅ 集合交/差，sorted 输出稳定 |
| parent/child 组装 | ✅ 多根森林 + sibling_order 排序 |
| main.py 双前缀注册 | ✅ `/runs` 与 `/api/runs` 均可用 |

### 5.2 前端 — 功能正确，测试基建弱

| 检查项 | 结论 |
|--------|------|
| API 路径 | ✅ `GET /api/comparisons/{id}/span-trees` 与后端一致 |
| 着色规则 | ✅ 对齐绿 `#e8f5e9`、仅侧橙 `#fff3e0`、默认灰 |
| 入口完整性 | ✅ 实验 summaries + diff_highlights 均有「Span 树」 |
| 弹层层级 | ✅ `zIndex: 2000`，点击遮罩关闭 |
| 空树 UX | ✅ 「无 Span 节点」文案 |
| 组件测试 | ❌ `package.json` 无 vitest |
| TS 严格 | ⚠️ 项目级 tsc 有多处历史 error；**P4 新增文件无 TS 错误** |

### 5.3 已知限制（设计内，非缺陷）

1. **仅 aggregate_key 对齐**，不用 name/type 兜底 — 符合 P-05。
2. **不展示 latency/token delta 高亮** — P4 MVP 范围，P4-CTO 已记录。
3. **一侧 Run 缺失时整接口 404** — 合理；空 Span 仍 200。

## 6. 风险与缺口

| 优先级 | 缺口 | 建议 |
|--------|------|------|
| P1 | 无前端自动化 | 引入 Vitest + RTL：`RunComparePanel` mock fetch、着色断言 |
| P1 | 无真实环境 E2E | 手工 P4-MAN-01~03 或 Playwright 脚本 |
| P2 | 无 OpenAPI schema 快照 | 可选：schemathesis / response JSON schema |
| P2 | 大数据量树性能 | 100+ 节点 Run 的 API 延迟基准（未测） |
| P3 | rollup 构建环境 | WSL 下 `npm run build` 缺 native 模块 — 环境待修 |
